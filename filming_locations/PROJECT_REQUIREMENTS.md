# 프로젝트 요구사항 정의서

## 서비스 정의

영상의 제목과 배경 캡처를 입력하면 시각적 단서와 외부 문서를 대조해 촬영지 후보를 찾고, 사용자가 검수한 장소를 지도와 지식 DB에 축적하는 RAG 서비스.

서비스명은 **장면에서 여행으로**다. 자료실의 항목 단위는 작품이 아니라 **실제 장소**다. 영화·드라마·유튜브·기타 영상 입력을 지원하지만 기본 수집 자료는 국내 영화 중심이다. 모든 영상의 장소를 찾는다고 보장하지 않는다.

## 도메인 선택 근거

- 기본 항목 266곳으로 약 100건 이상의 조건을 충족한다.
- 한국문화정보원의 공공 CSV 원문 장소설명 269건, 공식 관광/운영 안내 사실 요약 23건을 확보했다. 합계 292문서로 266곳 모두에 설명 자료가 연결된다.
- 장소별 출처·원문 행 번호·자료 기준일을 보존한다. 공공 원문의 설명은 짧고, 모든 촬영 관계를 독립 재검증한 것은 아니다.
- 근거가 필요한 질문: “서연의 집은 영화 당시 건물과 같은가?”, “초원사진관은 복원 공간인가?”, “작품 속 설정과 실제 촬영 장소가 같은가?”, “이 캡처를 해당 장소라고 보는 근거는 무엇인가?”, “자료에 없는 오늘 영업시간을 확정할 수 있는가?”
- 건강·금융 조언 도메인이 아니므로 전문가 조언 면책은 비대상이다. 대신 후보의 불확실성·세트/복원 여부·현재 출입/운영 정보 미확인을 안내한다.

## 선택 심화 및 추가 기능

- F2014 MMR: 유사도/MMR 전환을 제공하고 동일 질문의 근거 목록을 비교한다. lambda=0.5, 외부 문서 후보를 최대 20개 이상 범위에서 확보 후 최종 Top-k로 좁힌다. 작은 자료에서는 결과가 같을 수 있으며 정확도 향상을 보장하지 않는다.
- F2013: frontend/index.html·style.css·app.js와 FastAPI api.py를 분리했다. API로 질문·답변·인용 출처를 교환하고 장면 검색·검수 저장·지도·자료실을 제공한다.
- F2015: scripts/compare_rag.py에 5개 동일 질문의 기본 LLM/RAG 비교 실행과 판정 기록을 구현했다. 기본 실행은 GMS를 호출하지 않고 질문·실제 검색 근거·평가 양식을 만든다. 실제 모델 답변 비교는 사용자 요청으로 제외했다.
- F2016: 공공 CSV 원문 설명과 별도 공식 웹 조사 요약을 source_type별로 저장·색인한다. 새 사이트마다 수집 허용 여부를 확인하며 robots.txt 거부/확인 실패 시 건너뛴다.
- 지도 축소 시 밀집도와 장소 수 클러스터, 확대 시 개별 핀. 핀 클릭으로 장소 상세와 채팅 대상 변경.
- 검색 결과 검수 후 SQLite 저장, 중복 병합, 로컬 벡터 갱신. 사용자 확인은 기관 검증과 구분한다. 확인되지 않은 좌표는 임의 생성하지 않는다.
- GMS 일일 호출 제한·출력/문맥 예산·응답 캐시. 로컬 임베딩·의미 검색·지도는 GMS를 사용하지 않는다.

## 제출·검증 상태

설계는 RAG_DESIGN.md, 현재 판정은 IMPLEMENTATION_STATUS.md, 실제 로컬 설정 비교와 그래프는 data/validation에 둔다. 실제 GMS 실행, 실제 캡처 정확도·전체 처리 시간, 수업 제공 양식과 다른 교육생 상호 점검은 별도로 남아 있다. 미확인 사항을 통과로 표기하지 않는다.
